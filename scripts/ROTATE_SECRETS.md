# چرخش رازهای `secrets.cpp` (Phase 1, آیتم #۱)

این راهنما برای چرخش فوری `API_KEY`/`LICENSE_KEY` افشاشده در
[DEEP_CODE_AUDIT.md](../DEEP_CODE_AUDIT.md) است. این کار را
باید کسی با دسترسی به سرور production انجام دهد؛ این فایل و
`xor_secret_codec.php` فقط بخش کلاینت را آماده می‌کنند.

**یادآوری از گزارش:** XOR تک‌بایتی رمزنگاری نیست. چرخش کلید فقط زمان مهاجم
را کمی زیاد می‌کند — راه‌حل واقعی حذف کامل راز از کلاینت و رفتن به مدل
challenge–response است (Phase 2 آیتم #۱۰). این چرخش صرفاً یک اقدام موقت
اضطراری برای مقداری که همین الان افشا شده است.

## مراحل

1. **مقدار جدید تولید کنید** (سمت شما، جایی امن — نه در این ریپازیتوری):
   ```bash
   openssl rand -hex 20   # یا هر تولیدکننده‌ی راز امن دیگر
   ```

2. **سمت سرور** مقدار جدید را جایگزین کنید:
   - `API_KEY` → متغیر `UPDATE_CHECK_API_KEY` در `.env` سرور (بررسی‌شونده در `UtilityController.php:199`)
   - `LICENSE_KEY` → مقدار ستون `license_key` مرتبط در جدول `licenses`

3. **سمت کلاینت** مقدار جدید را با ابزار encode کنید:
   ```bash
   php scripts/xor_secret_codec.php encode "MAGHDAR_JADID"
   ```
   خروجی را در `app/src/main/cpp/secrets.cpp` جایگزین کنید:
   - `n7()` → `getApiKey()`
   - `n6()` → `getLicenseKey()`

   طول جدید آرایه را هم در فراخوانی `decryptXor(bytes, <LEN>)` همان تابع به‌روزرسانی کنید.

4. **build و deploy را هم‌زمان** انجام دهید — تا وقتی نسخه‌ی جدید APK منتشر
   و روی دستگاه‌ها نصب نشده، کلاینت‌های قدیمی با مقدار قدیمی درخواست
   می‌فرستند. برای گذار نرم، سرور می‌تواند برای یک بازه‌ی کوتاه هر دو مقدار
   (قدیمی و جدید) را بپذیرد، سپس قدیمی را حذف کند.

5. **راستی‌آزمایی:**
   ```bash
   php scripts/xor_secret_codec.php decode "0x.., 0x.., ..."   # آرایه‌ی جدید در secrets.cpp
   ```
   باید دقیقاً همان مقدار جدید را برگرداند.
